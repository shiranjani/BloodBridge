Abstract

Blood donation is a critical healthcare support activity. In emergency situations, patients and hospitals often need to find suitable blood donors quickly. Manual donor records, phone-based coordination and unorganized request tracking can delay this process. The Blood Donation System is developed to reduce these difficulties by providing a web-based platform for donors, users and administrators.

The system allows users to register, login, request blood, track request status and search for donors. Donors can update their profile, view assigned requests, respond to notifications and check donation activity. Administrators can manage donor records, approve and monitor blood requests, notify matching donors, maintain blood inventory, view expiry alerts, list user accounts and handle chat support conversations.

The project uses React for the frontend interface, Express.js and Node.js for backend APIs, and MySQL for persistent data storage. Passwords are stored using salted hashes. The system also includes validation, role-based navigation and automatic expiry status handling for blood inventory.

Chapter 1
Introduction

1.1 Introduction

Blood is an essential medical resource required during surgeries, accidents, childbirth complications, cancer treatments and many emergency cases. A successful blood donation process depends on the availability of donors, accurate donor details, quick communication and proper tracking of requests.

The Blood Donation System is a web application named Blood Bridge. It connects patients, normal users, donors, hospitals and administrators through a single organized platform. The application provides public pages, login and registration, donor search, blood request forms, admin dashboards and support chat features.

1.2 Problem Statement

In many situations, blood donor information is maintained manually or through scattered contact lists. This creates problems such as outdated donor records, delayed donor matching, lack of request status visibility, poor inventory tracking and difficulty in contacting the responsible administrator. These problems become serious during emergency blood requirements.

1.3 Objectives

  • To develop a web-based platform for managing donors, users and administrators.
  • To allow users and donors to submit normal or emergency blood requests.
  • To help administrators match requests with suitable donors based on blood group.
  • To maintain blood inventory with units, hospitals, status and expiry dates.
  • To provide notifications for donor responses and inventory expiry alerts.
  • To provide chat support between users/donors and administrators.

1.4 Scope of the Project

The scope of this project includes user registration, donor registration, role-based login, donor search, blood request submission, admin request management, donor notification handling, blood inventory maintenance, expiry alerts, profile updates, password changes and support conversations.

Chapter 2
Literature Review and Existing System

2.1 Literature Review

Healthcare management systems are designed to improve speed, accuracy and reliability in medical services. Blood donation management is one of the important areas where digital systems can reduce delays. A computerized system can store donor details, search donors by blood group and location, track requests and notify responsible users.

Modern web applications usually use a frontend framework, backend API and relational database. This separation improves maintainability. React helps create reusable components and dashboards, Express.js supports API endpoints and MySQL provides structured storage for donor, request, inventory and account records.

2.2 Existing System

In a manual blood donation process, donor details may be stored in notebooks, spreadsheets or phone contacts. When a request arrives, the administrator must manually search for donors and call them individually. Request status may not be visible to the requester, and inventory expiry may be missed if records are not checked regularly.

2.3 Disadvantages of Existing System

  • Donor records can become outdated or duplicated.
  • Searching donors manually takes more time.
  • Users cannot easily track their request status.
  • Inventory expiry dates are difficult to monitor manually.
  • Communication between donor, user and admin is not centralized.
  • Manual records are less secure and more difficult to back up.

2.4 Proposed System

The proposed Blood Donation System provides an online interface for all major roles. Users can request blood and search donors. Donors can manage profiles and respond to assigned requests. Administrators can create donor accounts, approve requests, notify matching donors, update request progress, maintain blood stock and communicate through chat support.

2.5 Advantages of Proposed System

  • Centralized MySQL database for donor, user, request and inventory data.
  • Role-based dashboards for admin, donor and user.
  • Faster donor matching using blood group and donor records.
  • Inventory expiry alerts for expired or soon-expiring stock.
  • Secure password storage using salted hash values.
  • Support chat conversation history for user assistance.

5.2 Frontend Implementation

The frontend is implemented with React. The main App component stores the active screen and current logged-in user. Protected screens such as admin, donor, user, request, donors and profile are guarded. Guests are redirected to login before opening protected pages.

The user interface is separated into pages and reusable components. DashboardLayout provides sidebar navigation for role-based dashboards. StatusBadge displays status values such as Pending, Approved, Accepted, Rejected, Available and Expired.

5.3 Backend Implementation

The backend uses Express.js. It loads database configuration from environment variables and creates a MySQL connection pool. On startup, it creates missing database tables and ensures that a default admin account is available.

Main API groups: /api/auth/register /api/auth/login /api/auth/change-password /api/donors /api/requests /api/inventory /api/users /api/admins /api/chat/conversations

5.4 Authentication and Security

User passwords are not returned to the frontend. The backend stores passwordHash and passwordSalt values generated with PBKDF2. The sanitizeUser function removes password related fields before sending account data to the client.

5.5 Donor Management Module

Administrators can add donor records with name, phone, blood group, location, birthday, last donation, username and password. The system also includes a donor credential generator based on donor name and birthday. Donor records are searchable using ID, name, phone, blood group and location.

5.6 Blood Request Module

Users, donors and admins can create blood requests. Request fields include requester, blood group, units, hospital, type and status. Admins can analyse requests, find matching donors, send notification status and update donor response status.

5.7 Blood Inventory and Expiry Alerts

The inventory module records blood group, unit count, hospital, expiry date and status. The backend checks expiry dates and marks expired items. The admin dashboard shows expiry alerts for stock that is expired or close to expiry.

5.8 Chat Support Module

The chat module allows guests, users and donors to start support conversations. Administrators can view support inbox messages, reply to conversations and close conversations. Chat messages are stored in the database with sender details and timestamps.

Chapter 7
Conclusion and Future Enhancement

7.1 Conclusion

The Blood Donation System successfully provides a web-based solution for organizing blood donation activities. It reduces manual record keeping by storing donors, users, requests, inventory and support conversations in a MySQL database. The role-based dashboards make the system easier to use for administrators, donors and normal users.

The project demonstrates practical use of React, Express.js, Node.js and MySQL. It also includes important application features such as password hashing, profile management, donor matching, request notifications and expiry alerts.

7.2 Limitations

  • The system currently uses dashboard notifications instead of SMS or email delivery.
  • Hospital accounts are not implemented as a separate role.
  • Location matching is text-based and does not use maps or distance calculation.
  • Advanced analytics and printable admin reports are not fully automated.

7.3 Future Enhancements

  • Add SMS and email notifications for urgent blood requests.
  • Add hospital role with hospital-specific request and stock management.
  • Integrate map-based donor search using location distance.
  • Add PDF report generation for donor lists, request history and inventory reports.
  • Add appointment scheduling for blood donation campaigns.
  • Deploy the project to a cloud server for real-world access.
